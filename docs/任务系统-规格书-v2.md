public static boolean isInRegion(Player player, String regionId) {
    RegionContainer container = WorldGuard.getInstance().getPlatform().getRegionContainer();
    RegionQuery query = container.createQuery();
    ApplicableRegionSet set = query.getApplicableRegions(
        BukkitAdapter.adapt(player.getLocation()));
    return set.getRegions().stream().anyMatch(r -> r.getId().equalsIgnoreCase(regionId));
}

> **⚠ 坑**：`getIdByItem()` 对普通物品返回 `null`（不抛异常）。
> **不要**用 `getName()` 或 CMD 手工匹配 —— 改名后会失效。

#### ★★★ 致命坑：`ItemBuilder` 在 Paper 1.20.1 上完全不可用（2026-09-15 实测）

本服是 **Paper 1.20.1**，而装的是 **Oraxen 1.218.0** —— 两者版本不匹配。

`ItemBuilder` 的字节码引用了 `org.bukkit.inventory.meta.components.FoodComponent`
（**Paper 1.20.5+** 才引入的类）。JVM 在加载 `ItemBuilder` **类本身**时就抛：

```
java.lang.NoClassDefFoundError:
    org/bukkit/inventory/meta/components/FoodComponent
```

**这意味着：任何对 `ItemBuilder` 的反射调用都会失败**，
包括 `build()`、`getType()`、`getOraxenMeta()`、`getItemStack()` —— 无一例外。

日志佐证：
```
Oraxen | Failed to load guarded NMS handler; NMS features will be disabled
```

##### 受影响 / 不受影响的 API

| API | 是否可用 | 说明 |
|---|---|---|
| `OraxenItems.exists(String)` | ✅ 可用 | 仅查内部 `Set`，不碰 ItemBuilder |
| `OraxenItems.getIdByItem(ItemStack)` | ✅ 可用 | 仅查 ItemMeta / PDC |
| `OraxenItems.getItemById(String)` | ❌ **不可用** | 返回 `ItemBuilder`，类加载即失败 |

**结论：物品「识别」一直正常，只有「构建展示物品」这条路是断的。**
这也解释了为什么 `kq selftest` 显示 22/22 图标 `exists=true`，
但 GUI 里图标全部回落成原版材质（书、木棍）。

##### 解决方案：绕开 ItemBuilder，直接读 Oraxen 配置

```java
// 从 plugins/Oraxen/items/*.yml 读取
Material material = Material.matchMaterial(node.getString("material"));
int cmd = node.getInt("Pack.custom_model_data");

ItemStack stack = new ItemStack(material, Math.max(1, Math.min(64, amount)));
if (cmd != 0) {
    ItemMeta im = stack.getItemMeta();
    im.setCustomModelData(cmd);
    stack.setItemMeta(im);
}
```

`OraxenHook` 保留了「原生 `build()` 优先」的双路径：
在版本匹配的服务器上走原生，失败才手工构建，做到高低版本都能跑。

##### 诊断命令 `/kq icon`

遍历配置中所有 UI 图标，输出 `配置= / exists= / 材质= / CMD= / 错误=`。

> **提示**：CMD 有值但客户端没贴图 = **资源包问题**；CMD 无值 = **插件问题**。
>
> 排查材质问题**第一步就该跑这条命令**，能立刻区分是插件还是资源包的锅。

##### 教训

1. 反射兜底不能只兜「方法调用失败」，还要考虑**类本身加载失败**；
2. **异常绝不能静默吞掉** —— 本次就是因为 `Hook.call` 静默吞异常，
   表面现象是「返回 null」，把排查方向带偏了好几轮。

## 5. SQLite 数据模型

路径：`plugins/KeranQuests/quests.db`

```sql
CREATE TABLE IF NOT EXISTS player_quest (
    uuid        TEXT NOT NULL,
    tree_id     TEXT NOT NULL,
    quest_id    TEXT NOT NULL,
    state       TEXT NOT NULL,       -- LOCKED/AVAILABLE/ACTIVE/COMPLETED/FAILED
    stage_index INTEGER DEFAULT 0,
    started_at  INTEGER,
    finished_at INTEGER,
    fail_reason TEXT,
    PRIMARY KEY (uuid, tree_id, quest_id)
);

CREATE TABLE IF NOT EXISTS quest_requirement (
    uuid         TEXT NOT NULL,
    tree_id      TEXT NOT NULL,
    quest_id     TEXT NOT NULL,
    stage_index  INTEGER NOT NULL,
    req_index    INTEGER NOT NULL,
    progress     INTEGER DEFAULT 0,
    PRIMARY KEY (uuid, tree_id, quest_id, stage_index, req_index)
);

CREATE TABLE IF NOT EXISTS quest_cooldown (
    uuid     TEXT NOT NULL,
    tree_id  TEXT NOT NULL,
    quest_id TEXT NOT NULL,
    kind     TEXT NOT NULL,          -- COOLDOWN / FAIL_LOCK
    until    INTEGER NOT NULL,
    PRIMARY KEY (uuid, tree_id, quest_id, kind)
);

CREATE TABLE IF NOT EXISTS tree_state (
    uuid    TEXT NOT NULL,
    tree_id TEXT NOT NULL,
    key     TEXT NOT NULL,           -- 如 "ch03_choice"
    value   TEXT,                    -- 如 "A" / "B"
    PRIMARY KEY (uuid, tree_id, key)
);

CREATE TABLE IF NOT EXISTS kill_log (          -- 防刷
    killer TEXT NOT NULL,
    victim TEXT NOT NULL,
    at     INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_kill_log ON kill_log (killer, victim, at);
```

**保存策略**：内存缓存 + 每 60 秒批量 flush + 退出/状态变更时立即写。**不在每个 tick 写库**。

### 6.5 生命周期命令（需求 #4）

四个挂载点，**全部支持多条 + 延迟**：

```yaml
on_start:
  - 'say {player} 开始了 {quest_name}'
  - 'delay 20 | title {player} title "&a" subtitle "&7任务已接取"'

on_stage_complete: []
on_complete:
  - 'kq reward {player} {quest_id}'
  - 'delay 40 | lp user {player} permission settemp ...'
on_fail:
  - 'title {player} title "&c任务失败"'
  - 'delay 20 | sound {player} entity.villager.no'
```

**延迟语法**：`delay <ticks> | <command>`
- 不含 `delay ` 前缀 → 立即执行
- 含 → 拆出 tick 数与命令体，用 `Bukkit.getScheduler().runTaskLater()`

**占位符**：

| 占位符 | 值 |
|---|---|
| `{player}` / `{uuid}` | 玩家名 / UUID |
| `{quest_id}` / `{quest_name}` | 任务 ID / 名 |
| `{tree_id}` | 任务树 ID |
| `{stage_id}` / `{stage_name}` | 阶段 ID / 名 |
| `{fail_reason}` | 失败原因（仅 on_fail） |

**执行身份**：控制台 `Bukkit.dispatchCommand(Bukkit.getConsoleSender(), cmd)`
**容错**：单条失败只记 warning，**不影响后续**（学 EP）

### 6.6 阶段可见性（需求 #7、#8）

```yaml
stage_visibility: FULL          # 全部阶段一开始就可见
stage_visibility: SEQUENTIAL    # 默认：完成前一阶段才显示下一阶段
stage_visibility: HIDDEN        # 只显示当前进度
```

**未解锁任务的显示规则**：

| 情况 | GUI 显示 |
|---|---|
| 前置全部完成 | 正常任务名 |
| 前置未完成，且**前置可见** | `🔒 需完成：接头、相逢` |
| 前置**本身也锁着** | `？？？`（不剧透） |
| "任意 N 个"前置 | `🔒 需完成以下任意 2 个：接头 / 相逢 / 第一桶金` |

判定：递归检查前置链，若前置 `state = LOCKED` → 上层显示 `？？？`。

### 6.9 互斥任务（需求 #11）

```yaml
# 写法 A：显式互斥
ch03a:
  exclusive_with: [ch03b, ch04, ch05]
  terminates_tree: true

# 写法 B：互斥组（推荐）
ch03a:
  exclusive_group: zhulong_ch03
  choice_group: zhulong_ch03_choice      # ★ 抉择组（GUI 二选一）
  terminates_tree: true
ch03b:
  exclusive_group: zhulong_ch03
  choice_group: zhulong_ch03_choice
```

**判定逻辑**：
1. 接取/完成某任务时，写 `(uuid, tree_id, exclusive_group, quest_id)` 到 `tree_state`
2. 判可接性时，检查该组是否已有**别的**任务被接取/完成
3. `terminates_tree: true` → 完成后写 `tree_state(terminated=true)`，
   整树所有任务永久回 `LOCKED`（**不可逆**，你已确认）

### 6.9.1 放弃任务机制（v1.0.2 新增）

为防止乱刷，任务可配置为**不可放弃**，或**放弃时受到惩罚**。

**默认行为：可以放弃 + 放弃扣除 5 生命值。**

**写法 A —— 简写（一键禁止放弃）**：
```yaml
main01:
  abandon: false      # 等价于 allowed: false
```

**写法 B —— 详写**：
```yaml
main01:
  abandon:
    allowed: true          # 是否允许放弃，默认 true
    health: true           # 是否扣血，默认 true
    health-cost: 5.0       # 扣除量（点），默认 5.0
    commands:              # 放弃时执行的命令
      - "say %player% 放弃了一个任务"
      - "delay 40 | effect give %player% slowness 10 1"
```

**要点**：
- `commands` 支持 `delay <ticks> | <命令>` 语法与 `%player%` 占位符；
- 扣血有**下限保护**（最低保留 0.5，避免直接死亡）；
- `Quest.fromConfig` 同时兼容简写布尔值与详写节，**老配置无需改动**。

## 10. 命令清单

### 10.1 `/kquests`（**第三方插件调用的控制台 API**）

| 命令 | 说明 |
|---|---|
| `/kquests accept <player> <quest>` | 接取任务 |
| `/kquests trigger <player> <key>` | ★ **触发自定义阶段**（EP/AccessCard 用） |
| `/kquests trigger <player> <tree>:<quest>:<stage>` | 精确触发某阶段 |
| `/kquests complete <player> <quest>` | 直接标记完成 |
| `/kquests fail <player> <quest> [reason]` | ★ **外部判失败** |
| `/kquests reset <player> <quest\|all>` | 重置进度 |
| `/kquests unlock <player> <quest>` | 强制解锁（调试） |
| `/kquests reward <player> <quest>` | 单独发奖励（内部） |
| `/kquests refresh <player>` | 重算可接性 |

**容错铁律**：`trigger` 遇到**不存在的 key** 或**玩家未接取该任务**时，

        text: '&7[深空联合联络员] &f烛龙站的情况比报告里糟糕。'

      - delay: 80
        text: '&7[深空联合联络员] &f准备好了就去找我。'
    freeze_player: true                  # 对话期间锁移动

### 11.2 接取链路

```
玩家右键 NPC
  └─→ NpcClickListener.onRightClick(NPCRightClickEvent)
        ├─ 匹配 NPC 名 → 找 dialogue 配置
        ├─ 启动 DialogueRunner（逐条延时发消息）
        └─ 对话结束 → 执行 after 命令
                       └─→ 提示玩家 "请打开 /kq 接取任务"
玩家手动 /kq → 打开 GUI → 自己点接取
```

**注意**：按你要求，**对话不自动接任务**，只提示玩家去菜单。玩家有掌控感。
