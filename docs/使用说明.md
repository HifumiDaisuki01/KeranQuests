## 二、给玩家用的命令

| 命令 | 作用 |
|---|---|
| `/kq` 或 `/kq list` | 打开任务菜单（任务树列表 → 点树看任务） |
| `/kq track [任务ID]` | 追踪某任务（影响 `%kq_current%`） |
| `/kq abandon [任务ID]` | 放弃任务 |
| `/ka` | 快速查看当前任务与进度 |

权限：`kq.use`（普通玩家）· `kq.admin`（管理员）· `kq.bypass.limit`（无视并发上限）

**管理员命令：** `/kq reload`（热重载配置）· `/kq selftest`（环境自检）· `/kq debug <玩家>`（查看玩家档案）

## 三、怎么写一棵任务树

### 3.1 最小可用模板

在 `plugins/KeranQuests/quests/` 下新建 `mytree.yml`：

```yaml
id: mytree                 # 必须与文件名一致
name: '&a我的任务'
order: 10                  # 排序，数字小的在前
enabled: true

quests:
  hello:
    name: '&f第一次打招呼'
    type: MAIN             # MAIN=主线 / SIDE=支线
    weight: 10             # 权重，越大越优先被 %kq_current% 选中
    stages:
      - requirements:
          - type: region_enter
            region: my_region      # ← 改成你的 WorldGuard 区域名
            world: world
            display: '前往集合点'
```

进游戏 `/kq reload`，就有一棵新树了。

### 3.2 要求类型（stages 里的 requirements）

一个阶段可以写多条要求，默认**全部完成**才算过。加 `mode: ANY` + `need: N` 就变成"满足 N 条即可"。

| type | 含义 | 关键字段 |
|---|---|---|
| `region_enter` | 进入区域 | `region` `world` |
| `region_stay` | 在区域内停留 N 秒 | `region` `world` `seconds` |
| `mm_kill` | 击杀 MythicMobs 怪物 | `mobs`（列表）`count` |
| `player_kill` | 击杀玩家 | `count` `region`（限定区域）`same_victim_cooldown`（防刷） |
| `oraxen_item` | 收集 Oraxen 物品 | `item` `count` `consume`（true=上交扣除） |
| `npc_talk` | 与 NPC 对话 | `npc`（Citizens NPC 名） |
| `custom_trigger` | **等第三方插件发信号** | `key`（见第六节） |
| `permission` | 需要某权限 | `permission` |

### 3.3 阶段可见性

```yaml
stages:
  - visibility: SEQUENTIAL   # 做完上一阶段才显示下一阶段
    # 不写默认 = ALL，阶段全部可见
```

前置任务没做时，GUI 里显示 `？？？`（未知任务），不会剧透。

### 3.4 生命周期命令

任务开始 / 每个阶段完成 / 整任务完成 / 失败时，都能自动执行一批命令：

```yaml
    on_start:
      - 'say {player} 接了任务'
      - 'delay 100 | give {player} bread 1'   # 100 tick = 5 秒后执行
    on_stage_complete:
      - 'say 阶段完成'
    on_complete:
      - 'lp user {player} permission set quest.done true'
    on_fail:
      - 'say 失败了，重来'
```

`{player}` 会自动替换成玩家名，命令以**控制台身份**执行。

### 3.5 限时 / 禁死 / 重置

```yaml
    failure:
      on_death: true             # 死亡即失败
      time_limit: 1800           # 限时 1800 秒
      reset_on_fail: WHOLE_QUEST # 失败后整任务重来（另有 STAGE / NONE）
      fail_cooldown: 60          # 失败后 60 秒内不能再接
      # forbidden_regions:       # 进入这些区域判失败
      #   - 'example_boss_room'
      # max_kills: 20            # 杀怪超过 20 个判失败
```

### 3.6 循环任务（每日/每周）

```yaml
    repeatable: true
    cooldown: 86400            # 秒。86400 = 24 小时
```

做完进入冷却，冷却期内接不了。剩余时间用 `%kq_cooldown_<树ID>:<任务ID>%` 查。

### 3.7 抉择分支（二选一）

```yaml
  main03:
    choice: true
    choice_group: zhulong_final     # 组名，同组只能选一个
    choices:
      - 'main03a'
      - 'main03b'
```

配了 `exclusive_group` 的任务一旦选了，另一个分支就再也接不了。

### 3.8 终结整棵树

```yaml
  main03a:
    terminates_tree: true      # 接了它，整棵树锁定，其它任务全部不可接
```

适合"真结局 / 坏结局"这种设计。

## 四、前置条件（解锁规则）

写在任务里，或写在整个树的头部（`prerequisites:`）：

```yaml
    prerequisites:
      quest_completed_all: ['zhulong:main01']    # 必须完成全部
      quest_completed_any: ['a', 'b', 'c']       # 任意几个
      quest_completed_any_need: 2                # 上面"任意"的数量
      tree_completed_all: ['tutorial']           # 必须通关某个树
      permission: 'group.vip'                    # 需要权限
      oraxen_items:                              # 需要持有物品
        - item: 'keycard'
          count: 1
          consume: true                          # 接任务时扣掉
      mode: ALL                                  # ALL=全满足（默认）/ ANY=满足 N 个
      need: 1
```

写前置时可以用全名 `zhulong:main01`，也可以只写短名 `main01`（同树内），插件自动补全。

## 六、和第三方插件联动（重点）

### 核心指令

```
/kquests trigger <玩家> <key>
```

**这是最重要的对外接口。** 它的特点是：
- 玩家**没接**对应任务 → 静默什么都不做
- `<key>` **不存在** → 静默什么都不做
- **绝不报错、绝不影响调用方**

所以你可以放心地把它写进任何插件的命令配置里。

### 触发键从哪来

任务里写的要求：

```yaml
          - type: custom_trigger
            key: sl_zhulong_extracted      # ← 这就是 key
            display: '完成数据抽取'
```

别的插件只要在合适的时机执行 `/kquests trigger {player} sl_zhulong_extracted`，这条要求就完成了。

### 典型接法

**撤离点插件 —— 撤离成功时：**
```yaml
switch:
  console-commands:
    - 'kquests trigger {player} sl_zhulong_extracted'
```

**MythicMobs —— 击杀 Boss 时：**
```yaml
Skills:
  - command{c="kquests trigger <caster.var.p> boss_down"} @self
```

**Citizens NPC 对话结束：**
```
/kquests talk {player} 示例向导
```

**WorldGuard 进门时**（用 `/rg flag` + command flag，或自己的监听插件）：
```
/kquests trigger {player} sl_zhulong_dooropen
```

### 其它 API 命令

| 命令 | 说明 |
|---|---|
| `/kquests accept <玩家> <任务ID>` | 接任务（**尊重前置与上限**） |
| `/kquests force <玩家> <任务ID>` | **无视**前置与上限强制接（给剧情演出用） |
| `/kquests trigger <玩家> <key>` | 触发 custom_trigger |
| `/kquests complete <玩家> <任务ID>` | 直接判定完成 |
| `/kquests stage <玩家> <任务ID> <序号>` | 跳到指定阶段 |
| `/kquests fail <玩家> <任务ID> [原因]` | 判定失败 |
| `/kquests reset <玩家> <任务ID>` | 清空该任务进度 |
| `/kquests talk <玩家> <NPC名>` | 等同于与该 NPC 对话 |
| `/kquests refresh <玩家> <任务ID\|*>` | 刷新界面/进度 |
| `/kquests query <玩家> <任务ID>` | 查询状态，输出 `KQ_QUERY <玩家> <任务> <状态> <阶段> <主线完成数> <支线完成数>` |
| `/kquests tree <玩家> <树ID> <状态>` | 直接设置树状态 |

`accept` 被拒时控制台会打印 `KQ_ACCEPT <玩家> <任务> REJECTED`，方便排查为什么没接上。

## 七、占位符（PlaceholderAPI，identifier = `kq`）

### 当前任务

| 占位符 | 含义 |
|---|---|
| `%kq_current%` | 当前任务名（追踪优先，否则取权重最高的） |
| `%kq_current_id%` | 当前任务 ID，如 `zhulong:main01` |
| `%kq_current_type%` | `主线` / `支线` |
| `%kq_current_stage%` | 当前阶段名 |
| `%kq_current_stage_index%` | 阶段序号（从 1 开始） |
| `%kq_current_stage_total%` | 总阶段数 |
| `%kq_current_req_1%` | 第 1 条要求的描述 |
| `%kq_current_req_1_progress%` | 第 1 条要求的进度，形如 `3/10` |
| `%kq_current_req_1_bar%` | 进度条（可视化） |
| `%kq_current_time_left%` | 限时任务剩余时间 |
| `%kq_current_weight%` | 当前任务权重 |

`req_` 后面的数字可以换成 2、3、4…… 对应第几条要求。

### 统计与查询

| 占位符 | 含义 |
|---|---|
| `%kq_active_count%` | 进行中任务总数 |
| `%kq_active_main%` | 进行中主线数 |
| `%kq_active_side%` | 进行中支线数 |
| `%kq_completed_total%` | 已完成任务总数 |
| `%kq_tree_<树ID>_main%` | 某树主线进度，如 `1/1` |
| `%kq_tree_<树ID>_side%` | 某树支线进度 |
| `%kq_tree_<树ID>_state%` | 某树状态文本 |
| `%kq_cooldown_<树ID>:<任务ID>%` | 循环任务剩余冷却 |
| `%kq_has_quest_<树ID>:<任务ID>%` | 是否已完成 → `true`/`false` |
| `%kq_can_accept_<树ID>:<任务ID>%` | 是否可接取 → `true`/`false` |

没有当前任务时，个人占位符显示 `config.yml` 里的 `placeholders.none`（默认 `无`）。

## 八、Citizens 机械式对话

配在 `plugins/KeranQuests/npc/dialogue.yml`：

```yaml
dialogues:
  - npc: '示例向导'            # Citizens NPC 名（必须完全一致）
    freeze_player: true        # 对话时冻结玩家
    lines:
      - delay: 0
        text: '&e欢迎来到营地。'
      - delay: 40            # 40 tick = 2 秒后说下一句
        text: '&7先四处看看，熟悉一下环境。'
    after:                     # 对话结束后执行
      - 'kquests trigger {player} tutorial_intro_done'
```

注意事项：
- 一个 NPC 只能配一条对话
- `delay` 是**从上一条算起的间隔**，不是绝对时间
- `after` 里的命令以控制台身份执行，`{player}` 替换成玩家名

## 九、常见操作

**加载新写的任务树 / 改完 yml 生效：**
```
/kq reload
```
不用重启服务器，不用重新编译。**注意：`/kq reload` 只重载任务树和对话，`config.yml` 的改动需要重启。**

**看某个玩家做到哪了：**
```
/kq debug <玩家>
```
会打印追踪中的任务、每条进度及阶段、剩余冷却。

**排查"为什么接不了任务"：**
```
/kquests accept <玩家> <任务ID>
```
控制台会打印 `KQ_ACCEPT ... OK` 或 `KQ_ACCEPT ... REJECTED`。被拒的常见原因：
1. 前置任务没完成
2. 同类型任务已达并发上限（主线默认 1、支线默认 3）
3. 在冷却期内
4. 整棵树已终结

**改并发上限：** 改 `config.yml` 的 `limits`，或写到任务树头部的 `main_quest_limit` / `side_quest_limit`（按树覆盖）。

## 十、你现在需要做什么

插件本身已经**做完并测过**了。示例里所有 `example_` 开头的东西、`示例` 开头的 NPC，都是**占位符**，需要你按服务器实际情况替换：

1. **建 WorldGuard 区域** —— 然后替换 `region:` 里的 `example_zhulong_station` 等
2. **建 Citizens NPC** —— 名字要和 `npc_talk` 的 `npc:` 以及 `dialogue.yml` 的 `npc:` 一致
3. **建 Oraxen 物品** —— 替换 `oraxen_item` 的 `item:`（目前只有 `scrap_metal` 是真实存在的）
4. **确认 MythicMobs 怪物 ID** —— 替换 `mobs:` 列表（MM 怪物 ID 大多含中文，写的时候注意引号）

替换完 `/kq reload`，就能正式玩了。
